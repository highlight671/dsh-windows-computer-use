## 0.1.1 · Harness 0.2.1-rc.3

日期：2026-10-24（北京时间）。本地环境：Windows 11 x64、Harness 0.2.1-rc.3、Node.js 24。代码使用插件仓库中的正式后台启动适配器，未注入模型请求，也未执行桌面输入。

| 检查 | 结果与范围 |
| --- | --- |
| Node 回归测试 | 16 项通过，无失败或跳过；在原有安装保护测试之外，覆盖普通请求不等待、桌面就绪等待、单次取消不影响共享初始化、失败隔离、断线/重连及停用清理。 |
| 原生首次请求 | 使用当前宿主的 Cordis、ToolRuntime、SkillRegistry、SystemPrompt 验证：MCP 未就绪时，普通提示词组装立即完成且包含就绪工具；仅桌面就绪调用等待；就绪后的下一步包含九工具与 MCP 指令。 |
| 原生失败与释放 | 模拟初始化失败后，普通提示词组装仍成功，就绪调用明确失败。停用后本地就绪工具、九个测试桌面工具和 Skill 均移除，原生清理执行一次。 |
| 真实 MCP | 在隔离进程中复用本机已有 Windows-MCP 0.8.8 运行时，使用本插件挂载原生 MCP；就绪检查确认准确九工具，仅调用 ControlStatus。输入动作 0 次，截图 0 张；停用后工具均移除，进程正常退出。 |
| 日常 profile | 本机手工 MCP 条目采用同一后台就绪模块。正常退出后从桌面入口启动，主窗口约 3.3 秒出现，后台 appReady 约 1.7 秒；MCP 后台约 4.1 秒完成并注册九工具。连续观察到片头不同帧并自然结束，桌宠和自动最大化正常。此为本机手工集成验收，不是独立插件的 GUI 安装或通用性能承诺。 |

就绪检查只证明原生工具已注册，不证明可以接管桌面；实际任务仍需 ControlStatus、用户授权及操作后的界面验收。未通过 GUI 将独立插件安装到日常 profile。未为 v0.1.1 重做 Python 安装、记事本输入或截图验收；安装实现未变，首次使用仍应做安全验收。

`scripts/verify-native.mjs` 可重跑原生验证；默认使用惰性的测试 MCP 实现，不接触桌面，指定已有 `--runtime` 才做真实只读连接。CI 在 Windows 上安装固定 rc.3 宿主 peer dependencies 后运行相同的原生组件检查。

此前的本机集成还完成过记事本安全验收：新建空白页、输入短标记、实际读回和截图识别；未保存或覆盖文件。独立发布插件没有再次自动输入记事本，也未通过 GUI 安装到日常 profile，因此不把此前测试当作本插件 GUI 安装验收已完成。

安装开发测试发现 uv 的默认 Python 注册行为。发布脚本已明确使用 `--no-bin --no-registry`，并隔离 Python、缓存和可执行入口目录；修正版已在全新目录重跑通过，检查未产生 Python 注册项。开发测试产生的、指向测试目录的那条注册项已经准确匹配路径后回退。该回退逻辑不属于插件或发布安装脚本。

已知限制：Windows-MCP 0.8.8 在 Python 3.14 下会输出 asyncio 事件循环策略弃用警告；本次不影响连接检查。未验证其他 Windows 架构或 Harness 版本。提示词与工具白名单不是完整安全沙箱；内部截图附件回收未实现。
